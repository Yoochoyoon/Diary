# 그림일기 웹·앱 통합 기획서 (블로그형 피드 중심)

## 1. 프로젝트 개요 및 핵심 컨셉
* **서비스 한 줄 정의:** 마우스나 터치로 직접 그림을 그리고 짧은 일기를 남기면, 블로그나 갤러리 피드처럼 한눈에 모아볼 수 있는 개인 그림일기 웹 서비스.
* **핵심 가치:** 복잡한 다이어리 관리(여러 권의 책장, 표지 꾸미기 등) 대신, 매일의 그림과 글을 빠르고 직관적으로 기록하고 한 화면에서 쭉 둘러보는 경험에 집중한다.
* **확장 방향:** 개인용 반응형 웹사이트(v1.0)로 시작해 기능을 안정화한 뒤, 꾸미기·공유 기능 및 모바일 앱(PWA / React Native)으로 확장한다.

---

## 2. 핵심 화면 및 기능 (v1.0 필수 범위)

첫 번째 버전은 아래 **3개 화면**의 흐름이 매끄럽게 동작하는 것을 목표로 한다.

### 2.1 메인 화면 (블로그형 피드 / 갤러리)
* 작성한 그림일기들이 블로그 포스트나 카드 형태로 한눈에 쭉 나열되는 첫 화면.
* 각 카드에는 **그린 그림 썸네일, 작성 날짜, 제목, 본문 요약**을 표시한다.
* 상단 또는 우측 하단에 **`+ 일기 쓰기`** 버튼을 배치해 즉시 작성 화면으로 이동할 수 있게 한다.

### 2.2 일기 작성 및 수정 화면 (그림판 + 글쓰기)
* **그림 그리기 영역 (HTML Canvas):**
  * 마우스/터치 드래그를 통한 자유로운 선 그리기
  * 기본 도구: 펜 색상 선택(3~5가지), 선 굵기 조절(얇게/굵게), 지우개, 전체 지우기
* **텍스트 입력 영역:**
  * 날짜 선택, 일기 제목 입력, 짧은 본문 글 작성
* **저장 및 취소:** 저장 시 그린 캔버스 화면을 이미지 데이터로 변환해 글과 함께 저장한다.

### 2.3 일기 상세 보기 화면 (또는 모달 팝업)
* 메인 피드에서 특정 일기 카드를 클릭했을 때 그림과 전체 글을 크게 읽는 화면.
* 해당 일기를 다시 고칠 수 있는 **`수정`** 버튼과 지울 수 있는 **`삭제`** 버튼을 제공한다.

## 3. 데이터 구조 및 기술 스택

### 3.1 사용 기술
| 영역 | 기술 | 역할 |
| :--- | :--- | :--- |
| **프론트엔드** | React + Vite | 컴포넌트 기반 UI 구현 및 그림판(Canvas) 제어 |
| **백엔드 / DB** | Supabase (PostgreSQL) | 일기 텍스트, 날짜, 이미지 경로 데이터 저장 및 추후 인증 관리 |
| **파일 저장소** | Supabase Storage | 사용자가 캔버스에 그린 그림을 이미지 파일(PNG)로 저장 |
| **버전 관리** | Git | 기능 단위 작업 내역 기록 및 관리 |

### 3.2 단순화된 데이터 모델 (`DiaryEntry`)
다이어리 책장과 페이지 계층을 없애고, **개별 그림일기(`DiaryEntry`)** 단일 테이블 구조로 단순화한다.
* `id`: 일기 고유 식별자 (PK)
* `date`: 일기 날짜
* `title`: 일기 제목
* `drawing_url`: 그린 그림 이미지 경로 (초기 테스트 시 Base64 데이터 URL, Supabase 연결 후 Storage URL 저장)
* `content`: 일기 본문 텍스트
* `created_at`: 생성 시각

## 4. 단계별 개발 로드맵

**원칙:** 한 번에 모든 기능을 만들지 않고, **① 화면 구조 스케치 → ② 임시 데이터로 화면 구현 → ③ 실제 DB/스토리지 연결** 순서로 작은 단위를 완성하며 진행한다.

1. **1단계: 화면 스케치 및 프로젝트 구조 세팅 (현재 단계)**
   * 종이에 3개 화면(메인 피드, 작성/수정, 상세 보기)의 레이아웃 스케치.
   * `src/` 내부에 `pages/`, `components/`, `data/` 폴더 생성 및 임시 데이터(`mockData.js`) 작성.
2. **2단계: 프론트엔드 핵심 화면 및 그림판 구현 (임시 데이터 기반)**
   * 임시 데이터 목록을 블로그형 피드 화면에 렌더링.
   * `<canvas>` 기반 그림 그리기 기능 및 글쓰기 폼 구현.
   * 작성·수정·삭제가 브라우저 메모리(React State) 상에서 동작하도록 연결.
3. **3단계: Supabase 연결 및 데이터 영구 저장**
   * Supabase 프로젝트 생성 및 `diary_entries` 테이블 구성.
   * 그린 그림을 PNG 파일로 변환해 Supabase Storage에 업로드하고, 반환된 URL과 텍스트를 DB에 저장.
   * 새로고침 및 재접속 시 저장된 그림일기 목록 불러오기 구현.
4. **4단계: 사용성 다듬기 및 웹 배포**
   * PC 및 모바일 터치 환경에서 그림이 자연스럽게 그려지는지 반응형 테스트.
   * 로딩 상태 및 저장 실패 알림 처리 후 웹 배포.

## 5. 추후 확장 기능 (v2.0 이후 후보)

v1.0의 기록·조회 흐름이 안정적으로 동작한 뒤 필요에 따라 순차적으로 추가한다.
* **꾸미기 확장:** 종이 질감 배경(모눈, 줄노트), 스티커 및 장식 요소 추가, 여러 권의 다이어리 폴더/태그 분류.
* **계정 및 공유:** 로그인 및 사용자별 권한 관리(Supabase RLS), 특정 그림일기 링크 공유 및 공개 범위 설정.
* **앱 확장:** PWA(웹 앱 설치) 지원 또는 React Native + Expo 기반 모바일 앱 전환 검토.
